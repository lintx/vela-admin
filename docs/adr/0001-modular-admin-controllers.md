# 将应用级通用编排下沉为模块化控制器

## 状态

已采纳。

## 日期

2026-07-23。

## 背景

`examples/admin/src/App.vue` 曾同时承担布局装配、设置持久化、主题生成与预览、标签页路由联动、页面缓存、滚动恢复和业务头部等职责。

问题不只是文件过长：设置、标签页和主题已是 Vela Admin 的通用能力，但业务应用仍需重复编排 service、路由、DOM 和持久化。生成项目也会继承这些代码。

本次治理遵循以下约束：

1. Demo 的功能、视觉和交互保持不变。
2. 通用后台能力进入 framework，品牌、鉴权、通知和用户菜单留在业务层。
3. 设置支持本地立即生效、远端加载、防抖保存、错误状态和重试。
4. 现有公开 API 尽量保持兼容。
5. 完整演示页不因行数机械拆分。

## 决策

### 1. 提供模块化控制器，不提供全能壳组件

framework 提供 Settings、Tabs 和 Theme 三个应用级控制器。根组件只组合控制器、`AdminLayout`、路由出口和业务插槽。

控制器保持独立，业务可以替换品牌、鉴权、通知和用户状态。`AdminLayout` 继续是受控组件，避免把当前巨型根组件转移成拥有大量 props、slots 和事件的 `AdminAppShell`。

### 2. SettingsService 管理统一设置快照

`SettingsService` 使用 `AdminConfig` 作为有效设置模型，覆盖布局、主题、自定义颜色和固定标签。新增偏好字段保持输入可选，归一化后补齐默认值。

设置快照带显式版本号。读取旧版扁平设置或无版本嵌套设置时迁移已知字段；未知未来版本安全回退到当前配置，避免错误解释数据。

`createAdminApp()` 创建并注入设置服务，组件通过 `useAdminApp()` 或 `useAdminSettings()` 访问。远端同步通过可选适配器提供，framework 不绑定 HTTP 客户端、鉴权协议或服务端存储结构。

#### 本地与远端语义

1. 应用先读取本地设置并立即应用。
2. UI 更新立即写入响应式状态和本地存储，不等待网络请求。
3. 业务在登录或会话恢复后按需调用 `loadRemoteSettings()`。
4. 远端字段覆盖本地同名字段，缺失字段保留本地值，结果再次归一化。
5. 远端加载更新当前状态和本地存储，但不自动回传，避免加载—保存循环。
6. 保存失败不回滚界面或本地设置。

#### 保存与并发语义

同步状态为 `idle`、`scheduled`、`syncing`、`synced` 或 `error`。

保存采用单 worker FIFO 协调器：

1. 自动保存默认防抖 500ms，并只提交防抖窗口内的最新快照。
2. 请求中继续修改时，在当前请求完成后追加最新快照。
3. 手动同步、重试和销毁屏障使用独立 waiter；旧任务失败不阻断后续任务。
4. 较早请求完成不能覆盖较新的待同步或错误状态。
5. `syncSettings()` 保存调用时的完整当前设置，`retrySync()` 重试最新本地状态。
6. `syncStatus`、`lastError` 通过只读 ref 暴露；保存任务和错误回调中的设置快照使用深克隆。
7. 销毁只刷新最终本地脏快照；重复销毁共享同一个结果。

浏览器强制关闭时普通异步请求不保证完成；需要更强保证时由业务适配器选择合适的传输机制。

### 3. Tabs Controller 编排路由与页面状态

`createTabsService()` 继续是纯状态服务，不依赖 Vue Router 或 DOM。`useAdminTabs()` 负责：

- 当前路由与标签同步。
- 关闭标签后的导航协调。
- 固定标签的恢复、权限校验、排序和持久化。
- KeepAlive 缓存版本、主动刷新和滚动位置恢复。
- 生命周期结束时清理 watch 和待处理回调。

主滚动容器通过可替换解析器获得，service 不硬编码业务 DOM。

### 4. Theme Controller 管理主题状态与预览事务

`useAdminTheme()` 统一读取和更新主题风格、模式、源颜色与自定义颜色，并负责动态主题应用和模式切换动画。

`useThemePreview()` 管理生成主题的临时预览、当前/预览切换、取消和确认。`AdminThemePreviewBar` 下沉为通用布局组件，`AdminThemeGenerator` 继续保持 UI 组件定位。

设置抽屉切换主题时，事件链向上传递真实分段按钮。鼠标、触控和键盘操作均优先使用实际触发元素计算动画圆心；只有无法取得有效元素时才回退视口中心。新增事件参数保持可选，旧监听器仍可只消费主题值。

### 5. Demo 保留业务边界

Demo 继续负责品牌 Logo、仓库链接、mock 会话、权限数据、通知、用户菜单和示例导航。通知、用户菜单、GitHub 和快捷主题切换集中在业务组件中。

完整的 sortable、context menu 和用户列表等页面继续以演示清晰度为先，不因文件行数单独拆分。代码或资源只有在引用追踪与行为验证共同确认无用时才删除。

## 兼容影响

1. 现有公开 service、配置和方法名称保持可用。
2. 新控制器从对应子入口导出，根入口继续聚合。
3. 设置同步适配器继续接收完整有效配置，旧的一参 `save(settings)` 保持可用。
4. 新增配置字段和主题事件参数均为可选。
5. Demo 延续原 storage key，旧设置通过版本迁移保留。
6. `createTabsService({ homePath })` 不产生实际标签语义，标记为 deprecated；改用 `fixedTabs` 或 `useAdminTabs()`。
7. 该弃用字段仅在下一个 major、调用方完成迁移且至少经过一个稳定版本的弃用窗口后才考虑移除。

## 影响

正面影响：生成项目不再复制通用编排；根组件回归装配职责；设置同步、标签页和主题工作流具有稳定、可测试的公共边界。

成本与风险：新增公开 API 需要长期维护兼容；设置同步存在异步竞态；Tabs Controller 同时接触路由、DOM 和生命周期，需要持续覆盖这些边界。

## 替代方案

### 提供完整 AdminAppShell

它能进一步缩短根组件，但会形成拥有大量 props、slots 和事件的全能组件，限制业务定制并转移复杂度，因此不采用。

### 仅在 Demo 内抽取 composable

它对公开 API 影响较小，但生成项目仍需携带通用设置、标签页和主题编排，不符合框架边界，因此不采用。
